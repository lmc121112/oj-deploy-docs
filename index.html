Bước 1 Kiến trúc tổng quan hệ thống

Hệ thống gồm 3 thành phần tách rời, giao tiếp qua PostgreSQL (Supabase):

Thành phần Công nghệ Nơi triển khai đề xuất
Database & RPC Supabase (PostgreSQL) Supabase Cloud (Free Tier)
Web Frontend (oj-web-app) Next.js (App Router), React, Ace Editor Vercel / Netlify / Node.js Server
Judge Worker (oj-judge-core) C++17 (libcurl, nlohmann-json, Linux Sandbox) Ubuntu / Debian VPS (22.04 / 24.04)

Bước 2 Khởi tạo Database trên Supabase

Đăng nhập Supabase Dashboard → tạo Project mới → mở SQL Editor → dán toàn bộ nội dung file schema.sql bên dưới và bấm Run:

-- 1. Bảng người dùng
CREATE TABLE IF NOT EXISTS public.users (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  username TEXT UNIQUE NOT NULL,
  password TEXT NOT NULL,
  role TEXT NOT NULL DEFAULT 'user',
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. Bảng kỳ thi (Contests)
CREATE TABLE IF NOT EXISTS public.contests (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  start_time TIMESTAMPTZ NOT NULL,
  end_time TIMESTAMPTZ NOT NULL,
  restrict_users BOOLEAN DEFAULT FALSE,
  allowed_users TEXT[] DEFAULT '{}',
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 3. Bảng đề bài (Problems)
CREATE TABLE IF NOT EXISTS public.problems (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  statement TEXT DEFAULT '',
  time_limit_ms INT DEFAULT 1000,
  memory_limit_mb INT DEFAULT 256,
  contest_id TEXT REFERENCES public.contests(id) ON DELETE SET NULL,
  problem_order INT DEFAULT 1,
  io_mode TEXT DEFAULT 'stdio',
  io_filename TEXT DEFAULT '',
  hide_tests BOOLEAN DEFAULT FALSE,
  hide_grading BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 4. Bảng bộ test (Test Cases)
CREATE TABLE IF NOT EXISTS public.test_cases (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  problem_id TEXT REFERENCES public.problems(id) ON DELETE CASCADE,
  test_order INT NOT NULL DEFAULT 1,
  input_data TEXT NOT NULL,
  expected_output TEXT NOT NULL
);

-- 5. Bảng lịch sử bài nộp (Submissions)
CREATE TABLE IF NOT EXISTS public.submissions (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  problem_id TEXT REFERENCES public.problems(id) ON DELETE CASCADE,
  username TEXT NOT NULL,
  language TEXT NOT NULL,
  source_code TEXT NOT NULL,
  status TEXT DEFAULT 'Pending',
  verdict TEXT DEFAULT '',
  exec_time_ms INT DEFAULT 0,
  memory_kb INT DEFAULT 0,
  compile_message TEXT DEFAULT '',
  test_results JSONB DEFAULT '[]'::jsonb,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 6. Bảng Template code mặc định theo ngôn ngữ
CREATE TABLE IF NOT EXISTS public.language_templates (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  language TEXT UNIQUE NOT NULL,
  display_name TEXT NOT NULL,
  template_code TEXT NOT NULL
);

RETURNS VOID

SECURITY DEFINER
AS $$
BEGIN
  TRUNCATE TABLE public.submissions, public.test_cases, public.problems, public.contests, public.users RESTART IDENTITY CASCADE;

Lưu ý API Keys: Vào Project Settings → API để lấy Project URL, anon public key (cho Web App) và service_role key (cho C++ Judge Core).

Bước 3 Triển khai Giao diện Web (oj-web-app)

3.1. Chạy thử trên máy cá nhân (Local)

git clone <link-repo-oj-web-app>
cd oj-web-app
npm install

cat <<EOF > .env.local
NEXT_PUBLIC_SUPABASE_URL=https://your-project-id.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-public-key
EOF

npm run dev

3.2. Đưa lên Internet miễn phí với Vercel

  1. Đẩy mã nguồn oj-web-app lên GitHub repository.
  2. Truy cập vercel.com → chọn Add New Project → Import repository.
  3. Trong Environment Variables, thêm NEXT_PUBLIC_SUPABASE_URL và NEXT_PUBLIC_SUPABASE_ANON_KEY.
  4. Bấm Deploy để nhận tên miền hoạt động.

Bước 4 Cài đặt Máy chấm C++ Judge Core (Linux VPS)

Khuyên dùng máy chủ Linux (Ubuntu 22.04 / 24.04) để cô lập tiến trình sandbox và giới hạn bộ nhớ/thời gian chính xác.

4.1. Cài đặt trình biên dịch và thư viện

sudo apt update
sudo apt install -y g++ make cmake libcurl4-openssl-dev nlohmann-json3-dev \
  python3 openjdk-17-jdk dotnet-sdk-8.0 rustc fp-compiler

4.2. Cấu hình và biên dịch judge.cpp

git clone <link-repo-oj-judge-core>
cd oj-judge-core

cat <<EOF > .env
SUPABASE_URL=https://your-project-id.supabase.co
SUPABASE_SERVICE_KEY=your-service-role-key
EOF

g++ -O3 -std=c++17 judge.cpp -o judge -lcurl -pthread
./judge

Bước 5 Chạy ngầm 24/7 với Systemd Service

Cài đặt service để trình chấm tự khởi động lại khi VPS khởi động lại hoặc gặp sự cố mạng:

sudo tee /etc/systemd/system/oj-judge.service > /dev/null <<EOF
[Unit]
Description=Online Judge C++ Core Worker
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/oj-judge-core
ExecStart=/root/oj-judge-core/judge
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable oj-judge
sudo systemctl start oj-judge
sudo journalctl -u oj-judge -f

Bước 6 Kiểm thử sau khi triển khai

  • Khởi tạo Admin đầu tiên: Đăng ký tài khoản đầu tiên trên Web → vào bảng users trên Supabase đổi cột role thành admin.
  • Kiểm thử luồng chuẩn (stdin/stdout): Nộp thử bài mẫu aplusb bằng C++ và Python để xác nhận verdict AC.
  • Kiểm thử File I/O (.in/.out): Tạo 1 bài chọn chế độ File I/O, nộp code dùng freopen để kiểm tra trình chấm tự dọn sandbox.
  • Kiểm thử Contest & OI Mode: Tạo Contest bắt đầu ngay, nhân bản bài từ Luyện tập tự do vào Contest và kiểm tra tính năng ẩn kết quả trong giờ thi.
