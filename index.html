Tài liệu Vận hành & Sử dụng Hệ thống Online Judge

Hệ thống Online Judge được thiết kế theo kiến trúc tách rời giữa giao diện Web, cơ sở dữ liệu hàng đợi và lõi chấm bài cô lập sandbox, gồm 3 thành phần chính:

oj-web-app

Frontend Next.js + Ace Editor

Giao diện nộp bài, quản trị đề/kỳ thi, render đề bài Markdown + KaTeX và theo dõi chấm real-time.

Supabase

PostgreSQL & Hàng đợi

Lưu trữ tài khoản, đề bài, test cases, kỳ thi, code mẫu và hàng đợi bài nộp Pending → Finished.

oj-judge-core

Lõi chấm C++ & Isolate

Biên dịch và chạy code thí sinh trong sandbox isolate, đo thời gian (ms), bộ nhớ (KB) chính xác.

Luồng xử lý một bài nộp

  1. Thí sinh gửi mã nguồn trên Web (oj-web-app); bản ghi mới được tạo trong bảng submissions với trạng thái Pending.
  2. Worker chấm bài (trên VPS hoặc GitHub Actions) lấy bài Pending, tải test case từ bảng test_cases (hoặc thư mục tests/), biên dịch và thực thi từng test trong sandbox isolate.
  3. Lõi judge.cpp cập nhật kết quả từng test (test_results), thời gian chạy lớn nhất (exec_time_ms), bộ nhớ (memory_kb) và chuyển trạng thái sang Finished.
  4. Trình duyệt của thí sinh tự động cập nhật kết quả mỗi 1 giây mà không cần tải lại trang.

3. Thiết lập Cơ sở dữ liệu Supabase

Tạo một dự án mới trên Supabase, mở mục SQL Editor và chạy tệp schema tương ứng với mô hình triển khai của bạn:

  • actions/schema-actions.sql: Dùng khi chấm bằng GitHub Actions.
  • vps/schema-vps.sql: Dùng khi chấm bằng VPS riêng (bổ sung bảng cấu hình đồng bộ và tối ưu hàng đợi).
Lấy khóa API: Vào Project Settings → API để sao chép Project URL, khóa anon public (dùng cho Frontend) và khóa service_role (chỉ dùng cho Worker chấm bài ở backend).

Các bảng dữ liệu cốt lõi

  • users: Thông tin tài khoản, vai trò (admin / thí sinh).
  • problems: Đề bài, giới hạn time_limit_ms, memory_limit_mb, io_mode, io_filename, hide_tests, hide_grading.
  • test_cases: Dữ liệu đầu vào (input_data) và đầu ra chuẩn (expected_output) sắp theo test_order.
  • contests: Danh sách kỳ thi, thời gian mở/đóng (start_time, end_time) và danh sách thí sinh được phép thi (allowed_users).
  • submissions: Hàng đợi bài nộp, mã nguồn, trạng thái chấm và mảng JSON test_results.
  • language_templates & system_settings: Lưu code mẫu mặc định cho từng ngôn ngữ.

4. Triển khai Worker chấm bằng GitHub Actions (Miễn phí)

Phù hợp cho lớp học, luyện tập cá nhân hoặc giải đấu nhỏ mà không cần thuê máy chủ VPS:

  1. Tạo repository chứa mã nguồn từ oj-judge-core (hoặc fork về tài khoản của bạn).
  2. Sao chép 2 tệp workflow actions/build-vendor.yml và actions/judge.yml vào thư mục .github/workflows/.
  3. Vào Settings → Secrets and variables → Actions của repository và thêm 2 biến bí mật:
    • SUPABASE_URL: URL dự án Supabase.
    • SUPABASE_SERVICE_KEY: Khóa service_role của Supabase.
  4. Chạy workflow Build Vendor một lần duy nhất để biên dịch sẵn vendor/bin/judge và vendor/bin/isolate.
  5. Workflow Judge sẽ tự động chạy theo lịch trình hoặc khi được kích hoạt để chấm toàn bộ các bài Pending.

5. Triển khai Worker VPS chạy 24/7 (Khuyên dùng cho Kỳ thi)

Để chấm bài tức thì (độ trễ dưới 1 giây) trong các kỳ thi chính thức, hãy triển khai oj-judge-core trên VPS Ubuntu 22.04/24.04:

Bước 1: Cài đặt trình biên dịch & biên dịch lõi chấm

bash (Ubuntu / Debian) 
sudo apt update && sudo apt install -y build-essential libcurl4-openssl-dev libcap-dev git python3 openjdk-17-jdk
git clone <link-repo-oj-judge-core> /opt/oj-judge
cd /opt/oj-judge
g++ -std=c++17 -O2 judge.cpp -lcurl -o vendor/bin/judge
chmod +x vendor/bin/judge vendor/bin/isolate

Bước 2: Cấu hình biến môi trường & systemd service

Sử dụng tệp vps/worker-vps.sh và vps/oj-judge.service để đăng ký dịch vụ chạy ngầm tự khởi động cùng hệ thống:

bash 
sudo cp vps/oj-judge.service /etc/systemd/system/oj-judge.service
sudo systemctl daemon-reload
sudo systemctl enable --now oj-judge.service
sudo systemctl status oj-judge.service
Lưu ý quyền cgroup/isolate: Dịch vụ oj-judge.service cần chạy dưới quyền root để isolate khởi tạo hộp cát (sandbox) và giới hạn bộ nhớ/CPU chính xác cho từng tiến trình.

6. Triển khai Giao diện Web (oj-web-app) lên Vercel

  1. Đẩy mã nguồn oj-web-app lên GitHub.
  2. Truy cập Vercel, chọn Add New Project và nhập repository oj-web-app.
  3. Khai báo 2 biến môi trường (Environment Variables):
    • NEXT_PUBLIC_SUPABASE_URL
    • NEXT_PUBLIC_SUPABASE_ANON_KEY
  4. Nhấn Deploy. Vercel sẽ tự động build ứng dụng Next.js và cấp tên miền HTTPS.

7. Hướng dẫn Soạn đề bài chuẩn Markdown + LaTeX

Trình hiển thị đề bài của OJ sử dụng bộ render MathText kết hợp GitHub Flavored Markdown (GFM) và KaTeX. Tác giả đề bài có thể viết tự nhiên như trên GitHub hoặc Codeforces:

Thành phần Cú pháp viết trong ô Nội dung đề bài Ghi chú
Công thức nội dòng $0 \le N \le 10^5$, $a_i + b_i$ Dùng dấu $ ... $
Công thức khối (căn giữa) $$\sum_{i=1}^{n} a_i = \frac{n(n+1)}{2}$$ Dùng cặp $$ ... $$
In đậm / In nghiêng / Code **Đề bài:**, *chú ý*, `stdin` Hỗ trợ đầy đủ GFM
Danh sách có thứ tự & gạch đầu dòng 1. Bước một hoặc * Dòng 1: ... Tự động thụt lề chuẩn
Đường kẻ ngang phân cách --- Tạo đường kẻ phân chia phần
Bảng ví dụ / Subtask | Input | Output |
| :--- | :--- |
| `A 5` | `B`<br>`15` | 		Hỗ trợ thẻ <br> để xuống dòng ngay trong ô bảng
Mẹo trình bày bảng: Bộ chuẩn hóa của MathText đã tự động xử lý khoảng trống trước bảng và chuyển đổi thẻ <br> thành xuống dòng thật trong ô bảng, giúp trình bày nhiều dòng Input/Output trong một ô cực kỳ gọn gàng.

8. Cấu hình Input/Output & Quản lý Test Cases

Hai chế độ đọc/ghi dữ liệu (io_mode)

  • Standard I/O (stdin / stdout): Thí sinh đọc từ bàn phím chuẩn và in ra màn hình chuẩn.
  • File I/O (file): Dùng cho các kỳ thi HSG truyền thống. Khi bật chế độ này và nhập io_filename = "BAI1", trang đề bài sẽ tự hiển thị hộp nhắc nhở thí sinh đọc từ BAI1.in và ghi ra BAI1.out, đồng thời lõi chấm tự động ánh xạ tệp trong sandbox.

Quản lý bộ test & Quyền hiển thị

  • Thứ tự test (test_order): Test có test_order nhỏ nhất sẽ tự động được lấy làm Ví dụ mẫu ở cuối trang đề bài (trừ khi bật tùy chọn ẩn test).
  • Ẩn ví dụ/test (hide_tests): Khi bật, hệ thống không hiển thị khung Ví dụ mẫu lấy từ bảng test_cases (hữu ích khi bạn đã tự kẻ bảng ví dụ bằng Markdown ngay trong phần nội dung đề bài).
  • Lưu trữ test trên Disk (oj-judge-core): Ngoài test lưu trên Supabase, lõi chấm hỗ trợ cấu trúc thư mục tests/<problem_id>/1.inp và 1.out.

9. Tổ chức Kỳ thi (Chế độ ICPC & OI)

Trong trang Quản trị (Admin), bạn có thể tạo kỳ thi và gán các bài tập vào kỳ thi thông qua mã contest_id:

  • Khung thời gian tự động: Trước start_time, thí sinh vào bài sẽ thấy màn hình khóa kèm đồng hồ đếm ngược Mở sau HH:MM:SS. Sau end_time, bài tự động khóa nộp bài (tài khoản admin luôn được phép xem và nộp thử mọi lúc).
  • Giới hạn danh sách thí sinh (restrict_users): Khi bật, chỉ những tài khoản có tên nằm trong mảng allowed_users mới truy cập được kỳ thi.
  • Chế độ ẩn điểm OI (hide_grading): Khi bật tùy chọn này trên bài tập thuộc Contest, thí sinh nộp bài sẽ nhận thông báo "Đã ghi nhận bài nộp" và toàn bộ trạng thái chấm từng test sẽ được giấu kín cho đến khi kỳ thi kết thúc.

10. Quản lý Code Mẫu Mặc định (Language Templates)

Khi thí sinh mở trang bài tập hoặc chuyển đổi ngôn ngữ trên Ace Editor, khung soạn thảo sẽ tự nạp đoạn mã khởi đầu tương ứng:

  • Hệ thống ưu tiên lấy cấu hình từ bảng system_settings (khóa code_templates do Admin chỉnh sửa trực tiếp trên web), sau đó mới lấy từ bảng language_templates.
  • Bạn có thể đặt sẵn khung #include <bits/stdc++.h> và tối ưu ios::sync_with_stdio(false); cin.tie(nullptr); cho C++ để thí sinh tiết kiệm thời gian gõ khuôn mẫu.

11. Quy trình Làm bài & Nộp bài cho Thí sinh

  1. Đăng nhập tài khoản ở góc trên bên phải màn hình.
  2. Mở bài tập từ mục Bài tập hoặc từ danh sách bài trong Kỳ thi (Contests).
  3. Đọc kỹ phần Input/Output trên thanh thông tin bài:
    • Nếu ghi stdin / stdout: Dùng nhập/xuất chuẩn (cin/cout, input()/print()...).
    • Nếu ghi File: TENBAI.in / TENBAI.out: Bắt buộc mở tệp đúng tên quy định để đọc dữ liệu và ghi kết quả.
  4. Chọn ngôn ngữ lập trình ở khung Gửi bài giải, viết code trực tiếp trên Ace Editor (hỗ trợ gợi ý cú pháp tự động) và nhấn 🚀 Nộp bài.
  5. Theo dõi kết quả chấm trực tiếp ngay bên dưới nút nộp bài hoặc bấm 📜 Lịch sử nộp bài để xem chi tiết từng test.

12. Giải thích Các Mã Trạng thái Chấm (Verdicts)

Mã Ý nghĩa Nguyên nhân thường gặp & Cách xử lý
AC Accepted (Chính xác) Chương trình vượt qua toàn bộ bộ test trong giới hạn thời gian và bộ nhớ.
WA Wrong Answer (Sai kết quả) Kết quả in ra khác đáp án chuẩn. Kiểm tra lại trường hợp biên, tràn số nguyên (dùng long long) hoặc định dạng xuống dòng.
TLE Time Limit Exceeded (Quá thời gian) Thuật toán chạy chậm hơn time_limit_ms. Cần tối ưu độ phức tạp thuật toán hoặc bật Fast I/O.
MLE Memory Limit Exceeded (Quá bộ nhớ) Khai báo mảng quá lớn hoặc đệ quy quá sâu vượt quá memory_limit_mb.
RE Runtime Error (Lỗi thực thi) Truy cập ngoài chỉ số mảng, chia cho 0, hoặc chương trình trả về mã thoát khác 0.
CE Compilation Error (Lỗi biên dịch) Sai cú pháp ngôn ngữ. Bấm xem chi tiết bài nộp để đọc thông báo lỗi từ trình biên dịch.
G Grading / Pending (Đang chấm) Bài nộp đang nằm trong hàng đợi hoặc đang được lõi chấm xử lý.

13. Quy chế Thi & Xem Chi tiết Từng Test

  • Thanh điều hướng nhanh: Khi làm bài trong một kỳ thi, cột bên phải màn hình hiển thị đồng hồ đếm ngược thời gian còn lại của kỳ thi và danh sách đánh số thứ tự các bài 1, 2, 3... để chuyển bài nhanh.
  • Xem chi tiết bài nộp: Trong trang Các bài nộp, nhấn vào nút Chi tiết trên mỗi bài nộp để mở hộp thoại xem từng test case (Input, Expected Output, Actual Output, thời gian chạy và bộ nhớ tiêu thụ của từng test).
  • Chế độ OI: Nếu kỳ thi áp dụng chế độ ẩn điểm trong giờ thi, kết quả chi tiết từng test sẽ tự động mở khóa ngay sau khi đồng hồ kỳ thi kết thúc.
