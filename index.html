⚡ Hướng dẫn Triển khai Hệ thống Online Judge

Chọn môi trường máy chấm bên dưới để xem hướng dẫn cài đặt đầy đủ cho Ubuntu 24.04 LTS (Noble Numbat).

Tổng quan

Kiến trúc GitHub Actions (Serverless + Precompute)

Hệ thống áp dụng kỹ thuật Precompute: đóng gói sẵn sandbox isolate và trình chấm judge.cpp vào thư mục vendor/ trên Ubuntu 24.04 (Noble Numbat). Nhờ đó, mỗi lần thí sinh nộp bài, máy ảo GitHub Actions chỉ mất < 1 giây để cài đặt môi trường thay vì phải apt-get và biên dịch lại từ đầu.

Thành phầnTệp cấu hình trong repo
Database Schemaactions/schema-actions.sql
Workflow Precompute (chạy 1 lần)actions/build-vendor.yml
Workflow chấm bài tự độngactions/judge.yml
Bước 1

Khởi tạo Database Supabase (actions/schema-actions.sql)

  1. Tạo Project mới trên Supabase → mở SQL Editor → New query.
  2. Dán toàn bộ nội dung tệp actions/schema-actions.sql và bấm Run.
  3. Vào Database → Replication, bật Realtime cho bảng submissions.
  4. Lưu lại Project URL, anon public key và service_role key tại Project Settings → API.
Bước 2

Cấu hình Repo Judge & Quyền ghi cho GitHub Actions

  1. Đẩy mã nguồn oj-judge-core lên GitHub, đặt hai tệp actions/build-vendor.yml và actions/judge.yml vào thư mục .github/workflows/ của repo oj-judge-core.
  2. Vào Settings → Secrets and variables → Actions, tạo 2 Secrets:
    • SUPABASE_URL: URL project Supabase
    • SUPABASE_SERVICE_ROLE_KEY: Service Role Key của Supabase
  3. Vào Settings → Actions → General → kéo xuống mục Workflow permissions → chọn Read and write permissions → bấm Save.
Bước 3 • Precompute

Đóng gói sẵn isolate & judge vào thư mục vendor/

  1. Vào tab Actions trên repo oj-judge-core → chọn workflow Build Offline Vendor Bundle (Ubuntu 24.04 Noble Numbat) → bấm Run workflow (chỉ chạy 1 lần duy nhất).
  2. Sau khi chạy xong (~30 giây), kiểm tra nhánh chính của repo đã tự động xuất hiện vendor/bin/isolate, vendor/bin/judge và nlohmann_json.hpp.
Lưu ý vận hành: Workflow chấm bài khóa cứng VERSION_CODENAME=noble (Ubuntu 24.04) và chạy với sudo -E ./judge. Khi nào bạn sửa code trong judge.cpp, chỉ cần chạy lại workflow Build Offline Vendor Bundle 1 lần để cập nhật tệp vendor/bin/judge mới.
Bước 4

Tạo Webhook kết nối Supabase → GitHub Actions

  1. Tạo GitHub Personal Access Token (classic) có quyền repo và workflow.
  2. Trên Supabase, vào Database → Webhooks → Create a new hook:
    • Table: submissions | Events: Insert
    • Method: POST | URL: https://api.github.com/repos/<USER>/oj-judge-core/dispatches
    • Headers: Authorization: Bearer <GITHUB_PAT> và Accept: application/vnd.github+json
Bước 5

Deploy Web Frontend & Khởi tạo Admin đầu tiên

  1. Import repo oj-web-app lên Vercel với 2 biến môi trường: 
    NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
  2. Truy cập trang web ngay sau khi deploy để hoàn tất khởi tạo tài khoản Admin đầu tiên.
Bảo mật: Hệ thống sẽ khóa toàn bộ giao diện cho tới khi tài khoản Admin đầu tiên được tạo xong.
Tổng quan

Kiến trúc VPS Linux (Chấm tức thì < 1 giây, không giới hạn phút chạy)

Phù hợp khi bạn có VPS riêng chạy Ubuntu 24.04 LTS (Noble Numbat). Trình chấm chạy dưới dạng dịch vụ nền systemd, nhận bài qua hàm hàng đợi nguyên tử claim_next_submission() mỗi 250ms và lưu cache bộ test trực tiếp trên RAM disk /dev/shm/oj_tc_cache.

Thành phầnTệp cấu hình trong repo
Database Schema + Atomic RPCvps/schema-vps.sql
Script vòng lặp Workervps/worker-vps.sh (đặt tại /opt/oj-judge/worker-vps.sh)
Dịch vụ hệ thống Systemdvps/oj-judge.service (đặt tại /etc/systemd/system/oj-judge.service)
Bước 1

Khởi tạo Database Supabase (vps/schema-vps.sql)

  1. Tạo Project trên Supabase → mở SQL Editor → New query.
  2. Dán toàn bộ nội dung tệp vps/schema-vps.sql (bao gồm bảng, index hàng đợi Pending và hàm RPC claim_next_submission()) rồi bấm Run.
  3. Vào Database → Replication, bật Realtime cho bảng submissions (không cần tạo Webhook).
Bước 2 • Precompute / Build

Cài đặt Isolate & Binary Judge Engine lên VPS

Trên VPS Ubuntu 24.04 (Noble Numbat), bạn có thể cài trực tiếp từ gói vendor/ đã precompute sẵn trong repo oj-judge-core hoặc biên dịch một lần duy nhất:

Cách A: Dùng trực tiếp gói vendor/ đã Precompute (Khuyên dùng - 5 giây)

sudo apt-get update && sudo apt-get install -y libcurl4t64 libcap2 libsystemd0 libseccomp2 python3 default-jdk g++
git clone https://github.com/<USER>/oj-judge-core.git /opt/oj-judge
cd /opt/oj-judge

sudo mkdir -p /usr/local/bin /usr/local/etc /run/isolate/locks /var/local/lib/isolate
sudo cp vendor/bin/isolate /usr/local/bin/
sudo cp vendor/bin/isolate-check-environment /usr/local/bin/ 2>/dev/null || true
sudo chown root:root /usr/local/bin/isolate && sudo chmod 4755 /usr/local/bin/isolate
sudo cp vendor/etc/isolate /usr/local/etc/isolate
echo "cg_root = /sys/fs/cgroup" | sudo tee -a /usr/local/etc/isolate
sudo useradd -r -s /usr/sbin/nologin isolate || true
echo "isolate:100000:65536" | sudo tee -a /etc/subuid /etc/subgid

cp vendor/bin/judge /opt/oj-judge/judge
chmod +x /opt/oj-judge/judge /opt/oj-judge/worker-vps.sh

Cách B: Biên dịch trực tiếp từ mã nguồn trên VPS

sudo apt-get update
sudo apt-get install -y libcurl4-openssl-dev libcap-dev libsystemd-dev libseccomp-dev build-essential git curl python3 default-jdk
git clone --depth 1 https://github.com/ioi/isolate.git /tmp/isolate
make -C /tmp/isolate isolate && sudo make -C /tmp/isolate install
cd /opt/oj-judge
g++ -O3 -std=c++20 judge.cpp -lcurl -o /opt/oj-judge/judge
Bước 3

Cấu hình biến môi trường & Kích hoạt vps/oj-judge.service

  1. Tạo tệp /opt/oj-judge/.env chứa thông tin kết nối Supabase (dùng service_role key): 
    cat << 'EOF' | sudo tee /opt/oj-judge/.env
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_KEY=eyJhbGciOi...service_role_key...
EOF
sudo chmod 600 /opt/oj-judge/.env
  2. Copy vps/worker-vps.sh vào /opt/oj-judge/ và vps/oj-judge.service vào /etc/systemd/system/: 
    sudo cp vps/worker-vps.sh /opt/oj-judge/worker-vps.sh
sudo chmod +x /opt/oj-judge/worker-vps.sh
sudo cp vps/oj-judge.service /etc/systemd/system/oj-judge.service
sudo systemctl daemon-reload
sudo systemctl enable --now oj-judge

# Kiểm tra trạng thái & log trực tiếp
sudo systemctl status oj-judge
sudo journalctl -u oj-judge -f
Mẹo hiệu năng: Bộ nhớ đệm test case /dev/shm/oj_tc_cache nằm trên RAM của VPS sẽ được giữ xuyên suốt giữa các lần nộp bài, giúp tốc độ nạp test gần như bằng 0 ms.
Bước 4

Deploy Web Frontend & Khởi tạo Admin đầu tiên

  1. Deploy oj-web-app lên Vercel hoặc chạy trực tiếp trên VPS bằng PM2/Node.js với 2 biến: 
    NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
  2. Mở trình duyệt truy cập trang web lần đầu và tạo tài khoản Quản trị viên (Admin) để mở khóa hệ thống.
